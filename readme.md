# 🛡️ rkn-guard

`rkn-guard` — утилита для Linux, предназначенная для блокировки подсетей сканеров с помощью `ipset` и `iptables`.  
Утилита автоматически применяет правила фильтрации, сохраняет их после перезагрузки системы и ведёт журналы подключений.
ps значительно снижает вероятность недоступности(бана) вашего ipv4 адреса из рф ^)

## 🛡️ От чего защищает

`rkn-guard` защищает сервер от массового сканирования портов и нежелательных подключений со стороны известных «сканерных» подсетей.

Это публичные IP-адреса и подсети российских государственных органов и аффилированных организаций (МВД, ФСБ, Роскомнадзор, ФНС, ФТС, суды, казначейство, МЧС и др.), собранные из открытых источников (RIPE NCC, whois и т.п.).

### Что именно блокируется

* Массовое сканирование портов
* Автоматические попытки подключений к SSH, веб-серверам, базам данных и другим сервисам
* Трафик, который создаёт лишнюю нагрузку и засоряет логи

### Преимущества

* Трафик отбрасывается **на уровне iptables/ipset** — до того, как пакеты дойдут до ваших сервисов
* Снижается нагрузка на CPU, память и сеть
* Уменьшается «шум» в логах
* Сервер реже попадает в базы данных, формируемые по результатам сканирований

Можно дополнительно использовать др списки или свои собственные списки.

## 📦 Установка

### Требования

Для работы необходимы:

* Linux с `systemd`
* `root`-права или доступ к `sudo`
* `iptables`
* `ipset`
* `curl`
* `python3` для сбора и отображения статистики (установщик добавляет пакет)

Установщик загрузит основной бинарный файл и установит команду управления:

```bash
rkn
```

### Быстрая установка

```bash
curl -fsSL https://raw.githubusercontent.com/Flecksis/rkn-guard/master/install.sh | sudo bash -s -- install
```

В конце установки появится запрос автообновления подсетей. Ответ `y` или `Y`
включает ежедневный запуск в **06:00 по локальному времени сервера**. `n`, `N`
или Enter не включают новый таймер; при переустановке прежнее расписание сохраняется.
Повторное согласие использует тот же таймер, без дублирования заданий.

## 🖥️ Управление

После установки запустите:

```bash
rkn
```
! Стоит регулярно обновлять само меню пунктом 6, и списки пунктом 5.
Откроется интерактивное меню управления `rkn-guard`.

Через него доступны:

* просмотр статистики;
* просмотр журналов;
* ручная блокировка IP;
* обновление списков;
* обновление `rkn-guard`;
* переустановка;
* удаление.

### Топ атак (CSV)

Пункт 1 и команда `sudo rkn-guard stats` собирают новые события из логов и показывают
все зарегистрированные IPv4/IPv6-адреса по убыванию числа событий. Отсутствие ASN
или имени сети не исключает адрес. Пустые данные сопровождаются сообщением,
некорректные строки CSV — диагностикой с номером строки.

CSV `/var/log/iptables-scanners-aggregate.csv` имеет разделитель `|`. При первом
запуске нового сборщика существующая статистика импортируется из него. Затем
источником сохранённой статистики становится `/var/lib/rkn-guard/attack-stats.json`:
счётчики и позиции чтения логов записываются вместе, CSV формируется заново.
Сырые логи не очищаются сборщиком; их ротацией управляет logrotate. Ротация самого
CSV отключена, чтобы история не обнулялась каждую неделю. Сбор по таймеру и из меню
использует общую блокировку `/run/rkn-guard-stats.lock`.

Это статистика **записанных в журнал событий**: действующий лимит LOG в iptables
не позволяет считать её полным числом всех отброшенных пакетов. Ранее потерянные
старым сборщиком события автоматически восстановить невозможно.

После ручной замены бинарника обновите установленный сборщик, не меняя firewall:

```bash
sudo rkn-guard setup-logging
sudo rkn-guard stats
```

### Обновление списков

В шапке меню показаны версия установленного бинарника, ветка его сборки и
результат проверки обновлений. Если вышел новый стабильный релиз, меню покажет
его номер. Проверка выполняется не чаще раза в десять минут, с коротким таймаутом;
ошибка сети отображается отдельно и не мешает пользоваться меню.

Старые бинарники не содержат имя ветки: для них выводится «неизвестна».
Сборки `dev` не сравниваются со стабильными релизами по номеру, но номер последнего
релиза всё равно виден.

В меню выберите:

```text
5. 🔄 Обновление списков и расписание
```

Обновляются только `ipset`-наборы.  
Существующий счётчик заблокированных подключений при этом **не сбрасывается**.

В пункте 5 доступны ручной запуск «Обновить сейчас» и настройка автообновления:

* **Каждые N часов** — целое число от 1 до 168. Первый запуск через N часов после
  включения таймера (или загрузки сервера), следующие — с интервалом N часов от начала предыдущего запуска.
* **По списку времени** — до 24 значений через запятую, например `6,12,18`
  или `06:00,18:30`. Повторы удаляются, время сортируется. Все значения — **МСК (Europe/Moscow)**,
  независимо от часового пояса сервера.
* **Ежедневно в 06:00 (МСК)** — готовый вариант.
* **Отключить автообновление** — прекращает будущие запуски; уже начавшееся обновление завершается.

Подменю показывает сохранённое расписание и состояние таймера. Настройки хранятся
в `/etc/rkn-guard-update.conf` и сохраняются после перезагрузки. Используются
один таймер `rkn-guard-update.timer` и один сервис `rkn-guard-update.service`;
cron-задания не создаются. Повторное сохранение того же активного расписания не
добавляет заданий и не откладывает следующий запуск. Для календарных режимов после
простоя выполняется один пропущенный запуск. При ошибке применения восстанавливаются
прежние файлы и состояние таймера; ошибка восстановления выводится отдельно.

Расписание 06:00, выбранное при установке, отображается как «локальное время сервера».
Это отдельный режим: готовый вариант 06:00 в подменю по-прежнему использует МСК.

Ручные и автоматические обновления вызывают одну команду `rkn-guard update` с теми же
источниками. Общая блокировка `/run/rkn-guard.lock` исключает одновременную работу
`update`, `full` и `uninstall`: конфликтующий запуск завершается с ошибкой и не ставится в очередь.
Нужны systemd и `flock` из пакета `util-linux`. Диагностика:

```bash
systemctl list-timers --all rkn-guard-update.timer
journalctl -u rkn-guard-update.service -n 50 --no-pager
```

### Доп списки подсетей

В пункте **9. Доп списки подсетей** можно добавить URL текстового списка, отдельно
включить, отключить или удалить каждый источник. Над действиями выводится
«Не рекомендуется». Добавление сначала проверяет данные и сохраняет список
**выключенным**. Включение, отключение и удаление сразу запускают обновление.
Если применение не удалось, настройки остаются сохранёнными для следующей попытки.

Поддерживаются HTTP(S), IPv4/IPv6 CIDR, пустые строки и комментарии после `#`.
Страница GitHub вида `.../blob/main/...` автоматически заменяется на raw URL.
Адрес без маски в дополнительном списке, неверная строка, пустой список, `/0`,
IPv4 в IPv6 и ответ больше 4 МиБ отклоняют весь источник. Основные списки сохраняют
поддержку отдельных IP. Повторы подсетей удаляются; пересечения между источниками
не исчезают при отключении одного из них. Можно добавить до 32 источников;
общий набор ограничен 65536 подсетями на каждое семейство, как и раньше.

Проверочный URL:

```text
https://raw.githubusercontent.com/C24Be/AS_Network_List/main/blacklists/blacklist-v4.txt
```

`https://raw.githubusercontent.com/shadow-netlab/traffic-guard-lists/refs/heads/main/public/skipa.list`
уже входит в основные списки. Второй раз добавлять его не нужно; меню отклонит дубликат.

Настройки, номера источников, последние проверенные данные и сведения об ошибках
хранятся в `/var/lib/rkn-guard/sources.json` с доступом только для root. Файл сохраняется
при перезапуске, обновлении и переустановке. Копии основных источников появляются
после первого успешного обновления новой версией. При ошибке загрузки или проверки
используется прежняя корректная копия именно этого URL. Если копии ещё нет, источник
пропускается с предупреждением; остальные источники обновляются. Пустой общий результат,
превышение лимита набора или ошибка сохранения не заменяют рабочие наборы.

Ручное обновление и существующий таймер используют один путь с `--managed-lists`.
Настройки и обновления защищает та же блокировка `/run/rkn-guard.lock`.
При частичном обновлении команда возвращает код **2**: исправные источники применены,
но были ошибки. В меню видны подробности, а systemd отмечает запуск как неуспешный;
таймер продолжает следующие запуски. Проверить сообщения можно так:

```bash
journalctl -u rkn-guard-update.service -n 100 --no-pager
```

Прямой `rkn-guard update -u ...` без `--managed-lists` сохраняет прежний строгий режим:
сбой любого URL отменяет обновление. Через CLI настройки доступны командой
`rkn-guard sources`; после изменения через CLI нужно запустить обновление отдельно.

### Обновление rkn-guard

В меню выберите:

```text
6. ⬆️ Обновить rkn-guard и меню
```

Будут загружены:

* свежая версия бинарного файла `rkn-guard`;
* актуальная версия скрипта меню.

Счётчики при обновлении также **не сбрасываются**.

## ⚙️ Прямой запуск

`rkn-guard` — основной бинарный файл проекта.  
При необходимости его можно использовать напрямую, без интерактивного меню.

### Применение полного набора правил

```bash
sudo rkn-guard full \
  -u https://raw.githubusercontent.com/shadow-netlab/traffic-guard-lists/refs/heads/main/public/government_networks.list \
  --enable-logging
```

### Справка

```bash
rkn-guard --help
```

### Удаление

```bash
sudo rkn-guard uninstall
```

> Внешний URL используется как источник списков и намеренно сохраняет исходное название файла в адресе.

## ⚖️ Правовой статус и легальность

### Что это такое юридически?

**rkn-guard** является легальным инструментом сетевой безопасности класса «firewall» (межсетевой экран).

### Правовая квалификация

1. **Это обычный firewall** — rkn-guard использует стандартные механизмы Linux (`iptables`/`ipset`), которые являются штатными компонентами операционной системы для управления сетевым трафиком.
2. **Законное право на защиту** — владелец сервера/инфраструктуры имеет полное законное право контролировать входящие соединения и блокировать нежелательный трафик.
3. **Аналог антивируса** — так же как антивирус блокирует вредоносные программы, rkn-guard блокирует подозрительный сетевой трафик.

### Что делает утилита с точки зрения закона?

* ✅ Блокирует входящие подключения к **вашему** серверу с определённых IP-адресов
* ✅ Не осуществляет атаки на другие системы
* ✅ Не перехватывает чужой трафик
* ✅ Не нарушает работу других систем
* ✅ Защищает только вашу инфраструктуру

Это аналогично тому, как вы закрываете дверь в свой дом или устанавливаете сигнализацию.

### Правовые основания (Российская Федерация)

**Статья 16 Федерального закона от 27.07.2006 N 149-ФЗ «Об информации»:**  
> Владелец информационной системы вправе устанавливать ограничения доступа к информации

**Статья 209 ГК РФ (право собственности):**  
> Собственник вправе по своему усмотрению совершать в отношении принадлежащего ему имущества любые действия

**Федеральный закон от 27.07.2006 N 152-ФЗ «О персональных данных»:**  
> Оператор обязан принимать необходимые меры по защите персональных данных

### Может ли быть привлечение к ответственности?

**НЕТ**, если вы:

* Используете утилиту для защиты **собственной** инфраструктуры
* Блокируете только **входящий** трафик на свой сервер
* Не используете для атак или нарушения работы других систем

**rkn-guard НЕ является:**

* ❌ Средством взлома
* ❌ Инструментом DDoS-атак
* ❌ ПО для незаконного доступа к информации
* ❌ Средством обхода защиты

Вы имеете право решать, кто может подключаться к вашему серверу.

### Для государственных органов

Если представители правоохранительных органов интересуются этой утилитой:

**rkn-guard** — это стандартный межсетевой экран (firewall), который:

1. Использует только легальные системные компоненты Linux (`iptables`, `ipset`)
2. Блокирует входящие соединения к защищаемому серверу
3. Не осуществляет никаких активных действий в сторону других систем
4. Является инструментом защиты информации, аналогичным коммерческим решениям (Cisco ASA, pfSense и т.д.)
5. Реализует требования по защите информации согласно 152-ФЗ и другим нормативным актам

Использование данной утилиты является законным осуществлением права на защиту собственной информационной инфраструктуры.
